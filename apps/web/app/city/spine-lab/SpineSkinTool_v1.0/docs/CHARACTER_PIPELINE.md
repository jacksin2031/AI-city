## 入口与正常操作

启动`scripts/start_trials.py --port 8783`，打开`/characters`。可选已有原照片，或用文件选择器导入PNG/JPEG/WebP；限24MiB和16777216像素，校正EXIF方向，新PNG去除元数据，原始字节私有存档，重复像素复用已有照片，永不覆盖原图。导入和保存计划不调用模型。然后填写管理名、可选衣装要求，选择订阅调用开关后“制作を開始”。真实调用还需要原有生成/审核设置及新的设计设置启用、上传同意和可用试验上限。界面显示的是本机预留计数，不是订阅余额。

默认自动设计并冻结，无需逐件选择。只有照片不足以形成设计、明确要求未支持的异袖，或选择“生成前に設計を確認・編集”才暂停。事实与自由设计分开；看不清下装由模型自由搭配，不可假称照片事实。photo-design-004显式要求圆顶实心衣身、紧凑低发髻/发饰、少量裙褶，并写明基础色/单块平涂影色/勾线色；约头宽1/3的发饰仅是实验提示词辅助，不是测量结论或质量门槛。当前标准腕只支持左右共用袖色/袖长：照片异袖事实保留在observed，造型简化成明确标记FREE_DESIGN的对称袖，不能承诺一侧裸臂。所有部位共享冻结的衣色、裤色、袖长和裙装选择。用户可在生成前编辑完整设计；冻结后需要新建任务，旧设计/任务不覆盖。

阶段为DESIGN→DESIGN_REVIEW→REQUESTS→GENERATE→ASSEMBLE→CAPTURE→VISION→REPAIR→DONE。一次继续自动推进可执行的全部后续步骤，而不是要求用户逐张点生成。裤装6张AI层、裙装8张AI层，另有2张本地标准腕；固定头模、五官和表情不重生，原耳所有状态隐藏，小耳和前发一起生成。每次生成都调用M04的原照片+五参考请求；从不把上次生成图回传。M05审核参考拼图002另含原角色头发与EriKari裙，仅作画风对照并绑定来源SHA，不进入任何生图输入。M05真实全身246帧后，明确可路由的缺陷交M06有限返修；未知或未定位则停止待审。

## 共用核心与来源

网页与`scripts/pipeline.py`共用pipeline_service；pipeline.py只编排M04的设计/请求/生成/全身装配、M05审核和M06返修。没有第二套图像API、模板裁切器或动画实现。photo_design通过现有execute_review_request读取原照片，结构化输出可见事实/完整衣装，禁止身份和敏感属性推断；生成仍使用现有官方Codex订阅ImageGen。当前CLI支持图片输入与JSON Schema输出，依据[官方CLI参数说明](https://learn.chatgpt.com/docs/cli/reference)；账户实际可用模型、内部工具次数、订阅余额或计费未由此证明。

design_prompt_revision、pipeline_schema、pipeline_revision、hair_fit_revision都由runtime/versions.toml读取。任务绑定照片SHA、设计、母版/atlas/原结构与风格图、质量政策、既定规范和流程版本；这些来源变化显式STALE。已冻结设计不再依赖后续分析提示词版本；已知001拟合可在002运行时按旧算法复验/回放，来源与算法记录不覆盖；未冻结分析仍拒绝该版本漂移，原分析请求和来源记录保留。任务记录逐件作业、原参考SHA、完整prompt SHA、标准腕非AI来源与缺陷审核链接。导出仍是运行JSON/atlas/PNG/manifest/ZIP，不伪装成编辑器.spine工程。

## 自动头发几何试配

新生成任务必须使用hair_fit，直接从母版固定head-base几何/alpha及新前后发的有效alpha计算尺度和位置。调用与装配相同的prepare_texture/region：在连续像素测量的候选尺度/顶部坐标网格中，比较冠顶/太阳穴覆盖、中央面部留空与后脑覆盖。head-alpha-fit-002保留前发求解，对后发独立搜索宽度与back_top；不用含侧发髻/蝴蝶结的前发总宽惩罚后发尺度。前后总宽差仅作为观察指标，不能机械等宽。001保留计算和复验，旧无back_top布局仍沿用原top；相同素材原样回放继承原拟合版本，显式重新试配才用新版。不从short/bob/updo三个手填值选择，也不修改母版骨骼/权重/曲线。

试配只改变新独立region的几何，不使用原角色轮廓蒙版，不修补/遮住新PNG裂缝，不增删有效图案。保留新原稿与规范化导出，原有透明留白处理仍由共用texture实现。hair-fit.json保存源头模、部件SHA、测量、布局与fit_id，并进入bundle哈希；审核从原稿重新计算验证，不用自报“已贴合”绕过检查。M06更换头发后沿用同一个试配器。

这些alpha区域只是技术代理指标，不能识别所有刘海结构、装饰、错画风或动态耳遮挡；ESTIMATED_NOT_VISUALLY_APPROVED不是美术PASS。三例试配都通过真实246帧，但耳部实际可见性等仍有待审，不能外推任意照片总能正确贴合。不能为了消除待审而放宽M05门槛。

## 持久状态、预算和停止

pipeline_store使用M06同一个事件链/fsync原子投影/OS租约实现的M07命名空间。每件job_id与发送意图先落盘，再由generation校验任务内的预留；外部不能拿flow_id跳过预算。重复启动由锁拒绝。生成返回后优先复用或本地收取；未知发送结果WAIT_RESULT，不清计数、不自动重发。已返回设计JSON也可本地恢复，命令/文件工具事件会被拒收。实际子进程退出后原生锁释放，恢复复用已发布包；本地渲染失败可另建审核重收，模型0。

默认图片总上限12、视觉3、返修最多2周期，真实设计/生成/审核默认关闭；保存后设置固定。单任务可配图片最多18、视觉最多3；逐部件初次、已知服务停止的新作业与M06返修累计最多3次，返修只用外层剩余预算。用户已授权本轮持续真实试验，私有全局上限相应增加；预留索引容量由versions.toml的execution.global_reservation_capacity统一定义，容量不是默认预算、服务余额或自动调用授权。旧预留全部保留。超过任一实际配置/任务上限明确停止，不删历史计数。

“停止した部位を新規作業で再試行”只针对明确返回UNAVAILABLE或CLI确证turn.failed额度终止。它保存旧作业/返回或事件SHA，不退预留；额度错误仍保留原图片/计费结果未知，开启的是新尝试而非宣称原请求未发送。操作本身不调用模型，随后advance才执行。普通超时、无结果、输出审核拦截和已返回GENERATED都不能走此入口。输出拦截停原任务；另选新设计的受控试验仍保留原失败，不能伪装原任务通过。

取消保存独立标记，并向正在编排的M06传播，停止后续步骤/选优，不能撤回已提交的远端处理。新建或切换页面不等于取消旧后台作业；操作回调绑定任务ID/页面代次，旧请求不能启动新任务或覆盖新页面。重复点击创建时立即冻结表单；新建任务重置真实调用和回放试配开关。

技术完成和美术批准分离：模型PASS仍只是辅助。只有有效完整人工审核通过可READY_FOR_REVIEWED_EXPORT；否则保留最佳/新候选供浏览，明确REQUIRES_REVIEW、UNKNOWN、拒绝或预算状态。最终包被修改后报告STALE并撤销显示的批准，下载也校验完整性。

## 浏览、导出与固定素材重放

## CLI

在工具根目录使用runtime/python/.venv/Scripts/python.exe（Windows），JSON请求和报告放私有runtime/work下。CLI与网页同核：

```powershell
python -B scripts/pipeline.py import-photo --input <用户明确选择的本地图片>
python -B scripts/pipeline.py create --input runtime/work/my-flow-request.json
python -B scripts/pipeline.py advance --id <flow-id>
python -B scripts/pipeline.py report --id <flow-id> --output runtime/work/my-flow-report.json
python -B scripts/pipeline.py design --input runtime/work/my-edited-design.json
python -B scripts/pipeline.py cancel --id <flow-id>
python -B scripts/pipeline.py retry --id <仅已知服务停止的flow-id>
python -B scripts/validate_pipeline.py --source runtime/work/M05/corrected/c01
```

创建请求为`mode=GENERATE, photo=character-referenceN.png, character_id=<管理名>`，可选constraints和limits；回放为`mode=REPLAY, source_output=<私有全身输出>, auto_fit=false`。编辑请求为`id`和完整`design`。不接受外部原稿路径或任意生成请求覆盖；只有明确的import-photo读取所选外部图片，先做图片边界检查再存入私有工作区。

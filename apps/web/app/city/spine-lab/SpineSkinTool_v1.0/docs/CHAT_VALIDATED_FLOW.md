## 历史013：先头发、后补耳、共同高度坐标（由014修订）

AI仅输出两个隔离的透明小耳片，按原头模肤色/深肉色线和本角色头发画风绘制。代码仅分离这些新生成耳片、整体等比缩放，按左右耳根共同head-local坐标定位，再合成进原前/后发PNG，头发和头模不重画、不按耳再定位。此处不是裁切原Spine头发或用头模轮廓蒙版。前后耳根高度共用同一数值，可因头发自然遮挡而只见部分；必须记录实际可见面积，遮挡未知不能伪称看到耳朵。原耳附件每个方向/表情仍隐藏，骨骼/曲线/原头五官不动。

输出保留无耳候选、前耳候选、前后耳候选及其材料/参考/审核/派生哈希与四项耗时。前耳未确认不制作背耳，头发未确认不补耳；未知、服务拦截或无效审核不得算完成。阶段通过不等于整人成品或生产授权。本轮每张照片输出一套新版角色候选，沿用此前每件初次后最多3次返修上限，不把“一版”误当成禁止纠错。未知或缺乏有效定向反馈时停止待审，不强行用满次数。

# 聊天验证后的照片到角色流程

原聊天三例对应007历史流程；当前统一工具版本由runtime/versions.toml管理：photo-to-skin-shared-013、image-prompt-013、photo-design-007、standard-arm-hand-002、head-alpha-fit-006。自动设计、装配、审核和返修的真实实测见CHARACTER_PIPELINE.md与evidence/M07-LIVE.md。原三例和新候选可浏览不等于生产美术批准；生产尺寸、16.5cm和自动语义放行仍未批准。

## 1. 每位角色独立锁定设计

一位角色选一张原始 character-reference*.png，不把三位人物的照片合成同一人的参考。网页可选择原照片；兼容原文件名、编号或连字符编号，拒绝路径穿越。每轮重新发送该原照片，不发送生成部件、预览或拼装图。

照片不完整时，部分衣装只是整体风格线索，AI 可自由搭配完整服装。明确可见的下装及用户明确指定才固定对应细节。记录已观察与自由设计内容，锁定整套衣服/裤子/鞋/发色与袖长，独立部件共享这份设计。不能从脸部推断个人身份或敏感属性来编造衣装事实。

## 2. 一次一个部件，按职责传说明

八个基本部件为前后发、衣身、腕、腿。原头模/五官/表情复用，原耳所有方向隐藏；小耳在前发PNG中一体生成。可选独立裙层为 SKIRT_FRONT/BACK。五张输入依次为原照片、中性画布、固定原头及耳根目标引导图、Harri 对应原部件、Davide/Spineboy 原部件风格板。裙子第四图改为原 EriKari 裙，借用展开结构而不照搬格纹/配色；头发风格参考只用原 body。

build_part_prompt 同时服务网页预检、实际订阅/本机生成和导出请求。将说明按目标部件筛选：不在 BODY 说明里要求袖子或完整衣装；不把完整真人衣服轮廓当作部件轮廓。

BODY 上沿是最高点在正中的连续凸弧；上部填满衣色。领口仅为内部短线。没有领口凹口、双肩峰、外翻角、袖子。下沿连续碗形，裤装时纯裤色带与 LEG 同色；不加独立裤子、口袋、门襟或人体分界线。裙摆独立，不并入 BODY。

正发以固定宽圆头模为尺度，照片侧拍转为正交正面。盘发前盖宽而浅、留出眉眼，不把后发髻/蝴蝶结贴在正面侧边。后发完整覆盖后脑；正背对比发顶、宽度、体积，允许后发髻/丝带等造型差异。长发按设计长度保留，不套用短发高度。

## 3. 标准手臂是确定性分支

本轮四次孤立手臂图被官方服务输出审核拒绝。经用户明确批准，腕默认采用原 Harri 结构，代码按袖色、固定肤色、袖长配色。原 alpha 和描边形状保持；配色同时映射袖/肩帽为深袖色边线、裸露皮肤和半圆手为深肉色边线，不能只保留最深肩线而抹去肉色线；肩帽、长筒、半圆无指手来自标准结构，前后可复用。网页选腕时切到标准配色，也可显式选择其他生成源。

该分支不调用模型、不上传照片、不占订阅请求次数；记录 ai_generated=false、model_calls_reserved=0 与模板哈希。不能伪装为 AI 成功。生成被拦截时不自动重试、不改走 API。

## 4. 原图留档，清理弱透明杂点并定位

模型原图可能有主体外极低 alpha 杂点；直接用 alpha>0 范围会把有效图算大，缩放后出现腿根空隙。texture.normalize_texture 保留原稿，对工作副本按实验阈值8清理弱透明噪点，记录删除 alpha 质量比例与主体范围，再等比缩放、底端对齐；不乘原附件 alpha、不按旧角色轮廓裁切。阈值不是所有图片通用的已批准生产设定。

头发画布、主体 bbox、world 几何分别记录。独立 region 取代旧角色头发 mesh，按当前头模校准；不用非等比拉伸或旧遮罩掩盖裂口/视角错误。character-layouts.json 中短发/bob/盘发数值仅来自本轮三例，未来新发型需复核。

完全不透明图不能靠旧附件 alpha 伪装成合格分层，导入时明确拒绝。标准腕在画布一致时保留 alpha，不经过模型图的噪点处理。

## 5. 共享设计书、全身导出与真实播放

当前正式实验入口为SHARED_CHARACTER_FLOW.md：design.py冻结设计和按字段筛选逐件说明，character_service同供网页和CLI，character_flow绑定原稿或生成job并调用唯一character核心。原聊天装配脚本仅为兼容包装，不是另一套算法。8层或含独立裙10层由设计书决定；标准腕按同一配色规则本地创建。

原照片/设计/提示词/参考哈希匹配后才接受job，拒绝旧单件导入绕行；原稿标为来源未核验。全部素材在私有目录快照后按共享规则装配。头发用独立region，裙使用原weighted mesh并启用对应裙骨骼。标准腕保留alpha与材质边线。

方向守卫在AnimationState.apply后执行，正侧腿→衣身/裙→腕→头部，背面腿→腕→衣身/裙→头部；旧版曾在非背视角恢复原耳；012所有方向隐藏原耳，小耳属于前发贴图，后发完整覆盖后脑。网页和CLI固定输入运行包/ZIP一致；预览绑定固定运行包，不能混读另一角色的可变当前资源。

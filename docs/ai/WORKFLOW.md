# 以 AI 为主的协作流程

## 每项任务

1. 由人确定目标、owner、文件范围、输入和验收标准。
2. AI 先读相关源码、contract 和测试，给出最小修改方案；不要加载整份历史或所有计划书。
3. 使用当前分支执行；共享文件由单人负责。优先复用 fixture，本地开发不需要密钥。
4. 运行适用验证，记录真实命令和结果；外部服务、浏览器、实机分开判定。
5. 提交 PR，由另一人检查 diff 和证据。CI 通过只是必要条件，不能替代视觉或业务判断。

## 可直接复制给 AI 的任务模板

```text
目标：
Owner：A / B / shared（指定实际负责人）
Issue：
允许修改：
输入与相关 contract：
禁止扩大：
验收条件：
需要运行的验证：
输出：修改文件、证据、未验证项、风险、commit/PR。
请先读根及模块 AGENTS.md，执行最小必要修改。
```

## 交接

交接写在 PR 或任务文档，包含接口样例、版本、已完成/待完成和下一条验证命令。不要只写“完成”“修好了”。需要子 Agent 时按实际价值使用，返回证据；不要让多个 Agent 同时改同一文件。AI 工具及账号由开发者自行选择，共用约束放在 AGENTS，避免绑定单一厂商。

`.agents/skills/ai-city-task/SKILL.md` 提供可复用任务入口；`CLAUDE.md` 和 Copilot instructions 指向同一套规则，避免复制多份互相冲突的项目规范。

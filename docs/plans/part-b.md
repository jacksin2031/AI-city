# AI City 项目计划书

B部分  角色生成与城市展示

V1.2 双人分工版    更新日期 2026年10月17日

本项目的核心目的是向路人直观展示 AI 的强大能力。主要服务对象为日本公众，通过手机创建自己的 Q 版分身，并在公共平板上观看角色入城、活动和交流，让没有技术背景的观众也能理解 AI 能做什么。

计划书使用简体中文，面向开发协作；产品界面统一使用日语，默认语言为 ja-JP。手机参与页、平板展示、问卷、资料卡、AI 对话、错误提示、隐私授权和管理界面均纳入日语验收。

### 项目定位与第一版边界

AI City 是线下 AI 互动展示，不以长期经营、写实 3D、大型多人在线游戏或完全自由聊天为首版目标。手机负责输入，平板负责展示，云端负责生成、数据与模型服务；首版采用单台平板作为城市本地模拟权威。

| 负责人 | 主责 | 交付边界 |
| --- | --- | --- |
| A | 手机参与流程与云端服务 | 访客流程、生成任务、授权、同步、文本 AI、管理与部署 |
| B | 角色生成与城市展示 | 外观抽取、模板素材、四方向、动画、Phaser 城市与行为调度 |

两份计划书属于同一个项目。每个模块只有一名主责人，跨模块变更需同步更新共享接口。技术、时间、成本和性能均为规划目标，不代表已经实测或完成验收。

## 1 展示目标与负责人职责

B 的交付目标是让日本路人一眼看到“像自己的分身正在城市中活动和交流”，以可辨认的形象、流畅动作和可理解的日语互动，展示 AI 的视觉理解、个性化创作与 Agent 交流能力。城市画面需要在无人直接控制时仍然值得观看。

### 展示体验与真实能力说明

- 拍照参与者看到形象预览及入城欢迎；没有参与的路人也能通过平板导览理解照片、角色、人格和对话之间的关系。

- 公共画面默认日语，重要提示简短易读。城市、资料卡、气泡、状态和 Demo 标识都不依赖中文或英文说明才能理解。

- 用真实处理状态说明 AI 在做什么：外观分析由模型辅助，模板和动画由程序实现，日语对话按需生成；不把程序移动或预设对话描述成模型实时生成。

- 优先确保“快、稳、像、可爱、有互动感”，不以更大地图、更多模型或更复杂模拟替代核心展示效果。

### B 主责范围

Avatar Service 的可见特征抽取、AvatarSpec、Fast Mode 模板组装、可选局部增强、四方向一致性、自动素材校验；Animation Library、Phaser City Engine、相遇与行为调度、镜头、入城表演、日语气泡、资料卡与展示端恢复。

### 与 A 的责任边界

A 提供任务、权限、受控照片输入、存储、公开事件和文本服务。B 输出可复用素材、质量结果、行为与展示模块。B 不自行公开参与者、不保存服务密钥、不读取原始私人问卷；生成模块所需照片由 A 在后台受控提供，展示平板不能读取。

首版采用单台平板作为本地模拟权威，目标 20–50 名活跃居民、同屏建议 8–20 人、最多 2–3 组可见气泡。

## 2 角色生成与模板生产

| 项目 | 规范 |
| --- | --- |
| 画风与比例 | 柔和、简洁、可爱的统一 Q 版；约 2.5–3 头身 |
| 素材方向 | 正面、背面、左侧、右侧；统一角色版本 |
| 素材结构 | 透明背景、分层部件、统一尺寸与锚点、可复用 Sprite Atlas |
| 特征优先级 | 发型、发色、服装类别与颜色、眼镜和明显配饰 |
| 输出 | AvatarSpec、AvatarManifest、质量结果、模式与回退标记 |

### 生成流程

接收 A 提供的受控照片引用后，检查单人主体、全身与清晰度，规范裁剪和透明边缘，提取可见外观特征并生成结构化 AvatarSpec，再选择发型、服装、鞋与配件模块组装角色。输入不足时返回标准错误或明确回退，不能从照片推断敏感属性。

### Fast Mode 为主路径

首版优先使用预制模块组合，确保全部方向及动画可用。先定义有限的发型、服饰和配件目录，统计真实照片的覆盖率。人物辨认度依赖外观取舍与素材质量，不能仅凭结构化字段保证。

### Enhanced Mode 为可选增强

只有当特殊发型或服饰无法表达且时延、成本允许时，才调用图像模型补充局部素材。增强失败、超时或质量不合格时使用 Fast Mode；不能拖延已有基础角色。A 负责调用编排与限额，B 负责增强输入规格、视觉处理和质量判断。

### 单张照片的能力边界

背面和被遮挡部分用模板合理补全，不声称准确恢复真实隐藏外观。相似度测试同时记录模板覆盖、回退比例与人工修正工时。原始照片只在后台受控处理，不进入平板缓存或公开资料卡。

生成时间保留 P95 不超过 30 秒的目标，由 A 统一计时；B 提供外观抽取、组装、增强和质量检查分段耗时，并分别记录 Fast Mode、Enhanced Mode 与回退结果。

## 3 四方向一致性与动画系统

同一居民的全部方向从唯一 AvatarSpec 和角色版本产生，禁止把四个方向当作无约束的独立绘图任务。头像放大、预览与城市场景使用同一套资产，避免“预览像本人，城市里变成另一个人”。

| 锁定层 | 控制内容 |
| --- | --- |
| 外观 | 发型 ID、服装 ID、色盘、眼镜与配件列表 |
| 结构 | 各方向模板、身体比例、关节锚点和前后遮挡 |
| 版本 | AvatarSpec、素材、rig、动画兼容版本 |
| 方向 | 对称部分可镜像；侧马尾、单肩包等使用独立资源 |
| 动画 | 共享动作与既有素材，不逐帧调用生成模型 |

### 骨架与工具选择

目标为可复用 Rig Template，覆盖头、躯干、肩肘手、髋膝脚和可选附属部件。P0 比较分层部件动画与骨骼 runtime，按视觉效果、设备性能、素材工时和授权成本选择；在通过验证前不锁定工具。新访客替换素材，不重新制作整套绑定。

| 状态 | 表现 | 级别 |
| --- | --- | --- |
| Idle | 呼吸、眨眼和轻微摆动 | P0 |
| Walk | 四方向行走、腿部交替与手臂摆动 | P0 |
| Turn | 约 0.15–0.3 秒的方向切换过渡 | P0 |
| Talk | 点头、轻手势、简化嘴形和气泡 | P0 |
| Wave | 入城和问候挥手 | P0 |
| Listen Happy Sit | 倾听、开心、休息姿势 | P1 或 P2 |

自动校验方向齐全、素材 ID 与色盘、头身比例、锚点、透明背景和动画遮挡。优先替换失败部件，必要时整体回退。真人是否可辨认必须通过参与者试用验证。

## 4 城市画面与平板交互

| 区域 | 用途 |
| --- | --- |
| 中央广场 | 入城入口、欢迎与初次问候 |
| 咖啡店 | 双人交流和休息 |
| 公园 | 散步、探索与偶遇 |
| AI 研究馆 | 围绕 AI 展示主题的交流 |
| 城市道路 | 连接区域、寻路与路过互动 |

### 场景与运动

使用预制可行走区域、建筑碰撞边界和适合地图规模的寻路算法。按深度排序处理建筑、树木和人物遮挡，限制居民重叠和拥挤。程序计算移动和动画，模型只返回高层意图，不直接控制逐帧坐标。

### 镜头与入场编排

支持全景、缩放、平移、点击聚焦和空闲自动巡游。新居民从广场入口出现，轻量光效和昵称提示后挥手约 3–5 秒，再恢复城市镜头。多人入城按事件队列展示，用户查看资料卡时不强制抢镜头。

### 居民资料卡

平板横屏右侧显示悬浮面板，展示与场景一致的角色放大图、获授权昵称、趣味性格或自填 MBTI、兴趣、区域和公开状态。MBTI 日语注明「本人入力」。只显示允许公开的最近对话，不展示照片或完整问卷；关闭后恢复镜头。缓存读取为主，点击不调用 AI，感知响应目标不超过 300 毫秒。

### 性能与设备

目标稳定 30 FPS，设备允许时争取 60 FPS。复用纹理和 atlas，控制尺寸、渲染层与气泡，减少远处更新和不可见角色绘制。20–50 活跃居民不等于全部同时渲染，同屏建议 8–20 人，可按分区、轮换和休眠处理。

在目标平板横屏、持续供电及防休眠条件下连续测试 4–8 小时，记录掉帧、内存增长、温度相关异常和恢复行为；桌面浏览器通过不能代替真实平板验收。

## 5 人格行为与自主社交

每位居民是拥有外观、偏好、位置、行动、兴趣、简单关系及有限公开互动摘要的逻辑 Agent，全部居民共享模型服务。首版不需要为每位参与者常驻独立模型实例，也不需要长期记忆系统。

### 自主行为

使用 A 提供的确定性人格参数，影响主动问候、探索地点、兴趣主题、即兴活动与表达偏好。行为包括散步、去目标区域、观察、休息、接近居民、聊天、结束互动和继续活动。人格参数只提供娱乐性偏好，不代表真人心理结论。

### 一次社交的完整流程

- 发现附近对象，检查距离、是否已互动、活动状态、全局并发、单角色冷却与公开资格。

- 按偏好和兴趣选择主题，寻路、转向并播放问候；同一居民不得同时参加多个互斥互动。

- 向 A 请求安全日语短对话，只传最小公开背景，等待期间保持本地动画流畅。

- 接收通过审核的内容后显示 1–2 句气泡并播放 Talk；按回合和时长上限结束。

- 只保存允许保留的最小互动摘要，然后恢复移动或待机。

### 安全与降级

不开放完全自由聊天，不让角色代替真人承诺、分享私人信息或表达从外貌推断的敏感结论。A 过滤模型输出，B 仍需拒绝结构不完整、版本过旧、角色已隐藏或删除的结果。超时、失败、超额或离线时使用已审查日语预设对话，且准确显示运行模式。

### 日语交流体验

默认简短、自然、友善的日语，适合日本公众观看。气泡保持可读字号、对比度和足够阅读时间；汉字、假名、全角标点及长昵称不得溢出。程序可控制同时可见 2–3 组，后台请求上限和费用由 A 另行约束。

AI 简介、对话、预设句库和问卷标签需统一日语词汇与语气，避免出现中文解释或未经处理的模型原文。

## 6 日语展示与运行恢复

公共平板应使路人无需先读长说明也能理解项目。空闲画面提供简短日语导览、参与二维码或指引，说明“照片变成角色，角色在城市中交流”；展示 AI 步骤时使用真实状态和简短说明，不持续遮挡城市。

| 场景 | 日语示例 | 规则 |
| --- | --- | --- |
| 参与入口 | あなたの分身を、この街へ | 与 A 的手机入口和二维码一致 |
| 欢迎 | 新しい住民がやってきました | 昵称通过审核且已授权 |
| 模型等待 | AIが会話を考えています | 仅在真实请求期间出现 |
| 模板回退 | テンプレートで作成しました | 不冒充完成 AI 图片增强 |
| 离线 | オフラインです | 说明新事件与实时 AI 暂停 |
| 演示模式 | デモモード | 预制角色和预设对话明确标识 |
| 维护 | ただいま準備中です | 暂停新参与，保留管理控制 |
| 资料卡 | プロフィール／興味／現在の様子 | 只显示获授权公开字段 |

### 缓存与恢复

缓存地图、必要字体、预制 Demo 资产和已授权居民素材。平板短时离线时可继续已有本地活动，但暂停云端事件与实时模型请求；重连先与 A 的快照、版本和删除标记对账。刷新后恢复有效居民，不重复播放全部历史入城。离线刷新和首次启动离线需单独测试，不假设有 Firestore 缓存就能加载全部游戏资源。

### 控制权与紧急处理

同一活动只允许一个有效模拟实例提交社交请求；重复标签页、休眠恢复和设备接管按共同规则处理。管理命令需校验版本，支持停止聊天、新增和特定内容。本机提供工作人员可用的暂停与隐藏操作；远程停止无法即时到达离线设备，采用展示有效期和重连清理补足。

Live、Demo、Maintenance 全部以日语呈现。日语字体与 fallback 应覆盖日文汉字、假名和标点，必要字体离线可用。管理界面由 A 实现，展示控制与视觉反馈由 B 配合。

## 7 双方接口与协作规则

先冻结最小共享字段，再使用同一组 fixture 开发。A 维护后端 API 与任务状态定义，B 维护 AvatarSpec、素材清单与动画兼容规则；双方共同确认后才能改变必填字段或状态语义。

| 接口 | 主要内容 | 主责 |
| --- | --- | --- |
| AvatarSpec | schemaVersion、模板与外观 ID、色盘、配件、不对称标记；不包含原始照片或问卷 | B |
| AvatarManifest | avatarVersion、四方向资源、透明尺寸、锚点、atlas、rigVersion、animationVersion、fallback 标记 | B |
| GenerationJob | jobId、状态、attempt、deadline、结果引用、错误码、取消标记、进度更新时间 | A |
| PublicResident | residentId、eventId、已授权显示字段、素材版本、公开状态、consentVersion | A |
| CityEvent | eventId、eventSeq、type、residentId、version；加入、更新、隐藏、删除及模式切换 | A |
| DialogueRequest 与 Result | 参与居民 ID、允许的公开上下文、日语输出、长度及安全结果；不传私人答案 | A |

### 角色生成交接

A 在有效授权和上传校验后创建任务，向 B 的生成模块提供受控照片引用、jobId、目标素材版本与截止时间。B 返回 AvatarSpec、AvatarManifest、质量结果或标准错误；由 A 保存状态并向手机提供进度。B 不自行创建公开居民，手机确认入城后由 A 发布公开事件。

### 对话交接

B 判断相遇、距离、冷却与互动资格后提交请求；A 校验权限、公开字段、预算和内容安全，再返回简短日语对话。B 负责播放、显示及结束互动。A 不逐帧控制动画，B 不在浏览器保存 Gemini 密钥。

### 并行开发与集成

- A 使用 B 提供的预制角色与素材清单 fixture 完成手机和云端；B 使用 A 提供的居民、事件与对话 fixture 完成城市。

- 素材错误、锚点错误及动画穿帮由 B 处理；任务遗失、重试、权限和存储问题由 A 处理。问题涉及双方时指定一名问题负责人。

- 每个可运行增量都进行集成；共享接口变更必须附兼容说明与样例。A 汇总项目验收记录，双方分别签认本模块结果。

## 8 开发里程碑与资源安排

原计划的 5–9 周为单名有经验开发者及可复用素材条件下的粗略估算。两人可以并行开发，但不能直接将工期减半；需在 P0 后根据美术工作量、目标平板、活动日期与实际吞吐重新排期。

| 阶段 | A 交付 | B 交付 | 通过条件 |
| --- | --- | --- | --- |
| P0 技术验证 | 最小上传、任务状态、确认与加入事件 | 照片到模板角色、四方向、五种动作与平板原型 | 一名访客完成入城；核心质量与延迟可测 |
| P1 城市与动画 | 公开居民与事件 fixture、同步基础 | 地图、寻路、镜头、动画、点击卡片 | 预制居民稳定活动；事件可消费 |
| P2 手机与生成 | 日语手机完整流程、授权、问卷、队列与恢复 | 真实生成模块、预览素材与质量回退 | 手机独立完成预览及确认入城 |
| P3 AI 与互动 | 日语文本服务、安全过滤、用量与预算 | 人格行为、社交调度、气泡与卡片 | 两角色完成安全日语对话且动画不阻塞 |
| P4 展场验收 | 并发、权限、费用、删除及网络故障测试 | 目标设备性能、视觉质量、离线和长时间测试 | 双方验收清单完成，失败项有处理结论 |

### 成本与资源

B 单独列出地图、发型、服装、配件、四方向适配、骨架绑定、动画、日语字形与人工修正工时。首版优先复用统一模板，AI 增强不进入关键路径。美术资产与动画工具的授权须单独核对，不能因引擎可免费商用而推定全部资产免费。

展示设备建议为 11–13 英寸、较强 WebGL 性能的平板，原计划建议 8GB RAM 或以上；最终以实际设备测试为准。现场准备稳定供电、支架、防休眠设置、网络和备用联网；全身照可由工作人员协助、支架自拍或相册上传。

### 主要协作风险

B 同时承担角色生产和城市画面，可能成为瓶颈。P0 应量化模板覆盖率和人工修正时间，优先缩减个性化种类；A 在接口稳定后承担素材上传、自动校验基础设施和运营工具，避免重复修改 B 的视觉模块。

## 9 验收交付与完成标准

| 验收项目 | 通过条件与证据 | 负责人 |

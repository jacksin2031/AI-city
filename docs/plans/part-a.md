# AI City 项目计划书

A部分  手机参与流程与云端服务

V1.2 双人分工版    更新日期 2026年10月17日

本项目的核心目的是向路人直观展示 AI 的强大能力。主要服务对象为日本公众，通过手机创建自己的 Q 版分身，并在公共平板上观看角色入城、活动和交流，让没有技术背景的观众也能理解 AI 能做什么。

计划书使用简体中文，面向开发协作；产品界面统一使用日语，默认语言为 ja-JP。手机参与页、平板展示、问卷、资料卡、AI 对话、错误提示、隐私授权和管理界面均纳入日语验收。

### 项目定位与第一版边界

AI City 是线下 AI 互动展示，不以长期经营、写实 3D、大型多人在线游戏或完全自由聊天为首版目标。手机负责输入，平板负责展示，云端负责生成、数据与模型服务；首版采用单台平板作为城市本地模拟权威。

| 负责人 | 主责 | 交付边界 |
| --- | --- | --- |
| A | 手机参与流程与云端服务 | 访客流程、生成任务、授权、同步、文本 AI、管理与部署 |
| B | 角色生成与城市展示 | 外观抽取、模板素材、四方向、动画、Phaser 城市与行为调度 |

两份计划书属于同一个项目。每个模块只有一名主责人，跨模块变更需同步更新共享接口。技术、时间、成本和性能均为规划目标，不代表已经实测或完成验收。

## 1 展示目标与负责人职责

A 的交付目标是让日本路人通过日语手机网页，完成照片、问卷、角色预览和明确授权，并可靠地把角色送到公共城市。流程应短、清楚、可恢复，让 AI 能力的展示不会被排队、错误或操作说明打断。

### 面向路人的体验设计

- 扫码无需安装 App 或注册账户。入口用简短日语说明参与方式、公开范围及照片用途。

- 上传照片后立即开始后台处理，并行展示六题问卷；将等待状态分为上传、排队、外观分析、角色组装与可预览，按真实状态显示。

- 说明照片理解、角色制作、人格偏好及 AI 对话之间的联系。模板组装、预设对话和 Demo 内容均准确标识，不把所有步骤描述成实时 AI 生成。

- 不参与拍照的路人仍可观看平板城市及简短日语导览；A 为现场二维码、操作说明和隐私提示提供统一日语文案。

### A 主责范围

Visitor Web、Backend API、Cloud Tasks 编排、任务持久化、Firestore 与 Cloud Storage 权限、问卷计分、Gemini 文本服务、内容过滤、Admin Console、监控、应用层预算限制、部署与现场运行手册。

### 与 B 的责任边界

B 负责照片可见特征抽取与 AvatarSpec、角色模板组装和动画资产；A 负责对这些模块的调用、受控数据传递、任务可靠性与公开发布。B 负责城市社交时机和角色行为；A 负责文本模型调用、安全结果和费用控制。

### 统一的首版约束

主要服务日本公众；所有 UI 使用日语。活动规模目标为 20–50 名活跃居民，同屏建议 8–20 人，可见气泡最多 2–3 组。第一版不包含写实重建、每人独立训练模型、长期经营或用户完全自由聊天。

## 2 手机参与流程与日语界面

| 步骤 | 手机行为与系统反馈 | 日语文案示例 |
| --- | --- | --- |
| 扫码 | 识别 Event ID，展示说明和活动状态 | AIシティへようこそ |
| 昵称与授权 | 昵称、照片处理同意、公开项目选择；建立本人会话 | 写真の利用について |
| 照片 | 拍摄或上传，检查单人、清晰度、全身和文件限制 | 写真を撮る／写真を選ぶ |
| 问卷 | 与生成并行；可跳过并使用中性偏好 | 質問に答える／スキップ |
| 等待 | 显示可理解的真实进度、重试或回退说明 | アバターを作成しています |
| 预览 | 查看形象、性格称号、公开字段及有限修正 | アバターを確認 |
| 入城 | 用户明确确认后发布；重复点击不创建重复居民 | 街に参加する |
| 完成与恢复 | 说明角色已加入；保留有效会话恢复和删除入口 | 街に参加しました |

### 容错体验

照片先完成时等待问卷，问卷先完成时展示性格说明等待角色。问卷跳过不得阻止生成；增强失败时返回保留主要颜色和可见特征的 Fast Mode 角色。手机断网后保留已接收的任务，恢复后显示实际结果。未经确认不得自动公开。

### 日语本地化要求

页面默认 ja-JP，按钮、提示、权限说明、输入校验、空状态、错误、问卷及授权文本使用自然日语。不要向访客直接显示内部错误码、英文异常或开发术语。昵称接受合理的日文及其他 Unicode 字符，不要求真实姓名；保留用户输入，不擅自翻译。

覆盖 Android Chrome 与 iPhone Safari 的拍摄、上传及返回操作。日语长句、假名、汉字和标点需实际检查换行、字形、按钮宽度及触控可用性。文案示例为开发参考，上线前完成日语校对。

## 3 云端架构与生成任务

| 组件 | 用途 |
| --- | --- |
| Next.js React TypeScript | 日语手机页、管理端与展示壳的 Web 基础 |
| Cloud Run | 授权、业务 API、模型调用及生成模块运行 |
| Cloud Tasks | 生成任务队列、重试、限流和截止时间 |
| Firestore | 私有任务、公开居民、活动、事件及运营数据 |
| Cloud Storage | 短期照片、角色资产及受控资源访问 |
| Gemini | 由 B 封装外观理解模块；由 A 提供简介与短对话服务 |
| 托管与监控 | 前端拟用 Firebase App Hosting 或合适平台；Cloud Logging 与 Monitoring |

### 任务生命周期

手机上传通过校验后立即返回 GenerationJob ID。建议状态为 QUEUED、RUNNING、READY、FAILED、CANCELLED；READY 同时带生成模式和回退结果。确认入城与生成完成是两个独立动作，不能把 READY 等同已公开。

A 接收 B 的受控输入输出，并执行状态持久化、结果版本校验、截止时间与重试上限。模型限流或增强超时不阻塞基础角色；已取消、已撤回或已删除的任务不得再次发布。

### 幂等与费用边界

同一有效任务复用已有结果，重复确认只创建一个居民；使用原子状态检查、执行租约和尝试记录处理重复投递。外部模型响应丢失时可能存在结果不明与再次收费，不能仅凭任务 ID 承诺外部调用绝不重复扣费，应限制重试并记录对账信息。

### 30 秒指标的量度

保留 P95 生成时间不超过 30 秒的目标。P0 冻结计时口径，建议从服务器接收有效上传至可预览素材就绪，包含排队和内部重试；网络上传耗时与用户手动重拍另列。Fast Mode、Enhanced Mode、回退率和确认后平板显示延迟分别统计。

## 4 问卷人格与日语文本服务

六题原创娱乐性问卷目标约 20–30 秒，覆盖社交主动性、探索偏好、处理问题方式、计划与即兴、兴趣活动和互动模式。问卷可跳过，采用中性参数；不得复制正式 MBTI 测评，也不得声称六题能科学推导人格类型。

| 参数 | 用途 |
| --- | --- |
| Sociability | 主动接触或等待别人发起的倾向 |
| Curiosity | 探索新地点和活动的倾向 |
| Empathy | 关怀与倾听的表达偏好 |
| Spontaneity | 计划与即兴活动偏好 |
| Interests 与 ActivityPreference | 允许公开的兴趣、区域与活动偏好 |
| DialogueStyle | 日语表达长度和语气，受安全及公共展示规则约束 |

### 确定性计分与公开范围

用确定性规则把答案映射为行为偏好，不为每一道题单独调用 AI。简介可由文本模型生成，并在公开前过滤。MBTI 仅作用户自填可选项，日语标注「本人入力」；未填时使用原创趣味性格称号。原始答案留在私有会话，展示端只接收允许公开的字段。

### AI 对话服务

B 提交符合距离、冷却和社交资格的对话请求；A 只提供最小必要公开背景，生成 1–2 句简短、安全的日语对话。输出必须通过结构、长度、语言及内容检查，失败时返回已审查的日语预设文本。模型等待不得阻塞城市动画。

集中限制同时请求数、每段回合、单角色冷却、token、每分钟调用与整场预算。可见气泡数由 B 控制，不能将 2–3 组可见气泡视为后端请求限额。角色不能代表真人承诺、泄露联系方式或推断敏感属性。

## 5 数据授权与隐私保护

| 数据类别 | 内容 | 读取边界 |
| --- | --- | --- |
| 私人会话 | 原始照片、问卷、授权记录、会话凭证 | 本人有效会话与获授权后端 |
| 角色资产 | AvatarSpec、四方向素材、动画版本 | 受控读取；公开版本按授权提供 |
| 公开资料 | 昵称、形象、性格、兴趣与公开活动 | 仅发布已经获得授权的字段 |
| 运营数据 | 活动、任务、错误、调用量与管理操作 | 管理员和后台服务 |

### 身份与访问控制

无注册体验仍需具备可验证的会话身份与授权。不可预测 ID 不能替代访问控制；访客只能操作自己的数据，展示平板只读活动内的授权公开资料，管理端使用强身份验证。Gemini 密钥仅在服务端。上传限制文件大小、格式、频率与活动容量，阻止批量滥用和跨活动读取。

### 分项同意与撤回

- 分别确认照片上传与 AI 处理、角色公共展示、昵称及性格兴趣公开，以及后续纪念卡分享。首版不把纪念卡作为交付前提。

- 日语说明谁可以看到角色、哪些信息公开、照片如何处理及如何删除。默认不收集真实姓名、地址或电话，不从外貌推断敏感属性。

- 提供本人可使用的删除方式，撤回后隐藏居民、停止新对话、取消未完成发布，并清理相关公开索引与资产。未成年人按活动及当地适用要求处理监护人同意。

### 保留期限与缓存清理

原始照片完成生成和必要检查后尽快删除；“最迟活动结束后 24 小时”保留为内部设计目标，由主办方最终确认。问卷、日志、备份和缓存分别定义保留策略。A 发布删除标记及版本，B 清理平板资源；离线设备无法即时接收远程撤回，需约定展示有效期、本机隐藏和重连对账规则。

## 6 实时同步与现场运营

手机确认后由 A 创建 PublicResident 与加入事件。平板监听当前活动公开集合，B 下载对应素材版本并排队播放欢迎。Firestore 用于资料和重要事件，不持续写入角色每帧位置。多屏或远程模拟迁移至后续阶段。

### 事件可靠性

事件带稳定 ID、顺序或版本信息，B 对重复、乱序及旧版本做幂等处理。刷新恢复先读取当前公开快照，再对账事件，不把所有历史加入重复播放。A 提供隐藏和删除状态，防止已移除居民因旧事件再次出现。

| 场景 | A 的处理 | B 的配合 |
| --- | --- | --- |
| 手机断网 | 任务保留，会话恢复后提供结果 | 生成结果保持可复用 |
| 平板短时离线 | 保留公开快照与变更版本 | 缓存城市继续运行，暂停新云端事件 |
| API 超时或限流 | 限制重试，提供明确错误与回退结果 | 使用模板角色或预设对话 |
| 平板刷新或接管 | 提供当前授权居民及有效素材版本 | 恢复资源、事件去重及本地状态 |
| 撤回或紧急停止 | 发布隐藏、删除或停止版本 | 在线即时处理；离线提供本机控制 |

### 管理系统

管理界面使用日语。提供居民与生成队列、失败原因和受控重试、内容审核、手动隐藏或删除、聊天终止、调用量与费用估算，以及 Live、Demo、Maintenance 模式切换。紧急停止可分别停止公开 AI 聊天、角色新增及不合适内容显示。

Demo 使用预制人物和已审查日语对话，明确标识「デモモード」，不冒充实时生成。预算警报用于提醒，应用层硬配额用于阻止继续调用。现场手册需写明网络、供电、防休眠、权限恢复及紧急处理步骤。

### 模拟权威

B 实现单一活动平板实例的本地模拟；A 提供活动与展示会话校验。两人共同定义重复标签页、平板休眠和设备接管的规则，避免两个实例同时提交同一居民的社交请求。

## 7 双方接口与协作规则

先冻结最小共享字段，再使用同一组 fixture 开发。A 维护后端 API 与任务状态定义，B 维护 AvatarSpec、素材清单与动画兼容规则；双方共同确认后才能改变必填字段或状态语义。

| 接口 | 主要内容 | 主责 |
| --- | --- | --- |
| AvatarSpec | schemaVersion、模板与外观 ID、色盘、配件、不对称标记；不包含原始照片或问卷 | B |
| AvatarManifest | avatarVersion、四方向资源、透明尺寸、锚点、atlas、rigVersion、animationVersion、fallback 标记 | B |
| GenerationJob | jobId、状态、attempt、deadline、结果引用、错误码、取消标记、进度更新时间 | A |
| PublicResident | residentId、eventId、已授权显示字段、素材版本、公开状态、consentVersion | A |
| CityEvent | eventId、eventSeq、type、residentId、version；加入、更新、隐藏、删除及模式切换 | A |
| DialogueRequest 与 Result | 参与居民 ID、允许的公开上下文、日语输出、长度及安全结果；不传私人答案 | A |

### 角色生成交接

A 在有效授权和上传校验后创建任务，向 B 的生成模块提供受控照片引用、jobId、目标素材版本与截止时间。B 返回 AvatarSpec、AvatarManifest、质量结果或标准错误；由 A 保存状态并向手机提供进度。B 不自行创建公开居民，手机确认入城后由 A 发布公开事件。

### 对话交接

B 判断相遇、距离、冷却与互动资格后提交请求；A 校验权限、公开字段、预算和内容安全，再返回简短日语对话。B 负责播放、显示及结束互动。A 不逐帧控制动画，B 不在浏览器保存 Gemini 密钥。

### 并行开发与集成

- A 使用 B 提供的预制角色与素材清单 fixture 完成手机和云端；B 使用 A 提供的居民、事件与对话 fixture 完成城市。

- 素材错误、锚点错误及动画穿帮由 B 处理；任务遗失、重试、权限和存储问题由 A 处理。问题涉及双方时指定一名问题负责人。

- 每个可运行增量都进行集成；共享接口变更必须附兼容说明与样例。A 汇总项目验收记录，双方分别签认本模块结果。

## 8 开发里程碑与资源安排

原计划的 5–9 周为单名有经验开发者及可复用素材条件下的粗略估算。两人可以并行开发，但不能直接将工期减半；需在 P0 后根据美术工作量、目标平板、活动日期与实际吞吐重新排期。

| 阶段 | A 交付 | B 交付 | 通过条件 |
| --- | --- | --- | --- |
| P0 技术验证 | 最小上传、任务状态、确认与加入事件 | 照片到模板角色、四方向、五种动作与平板原型 | 一名访客完成入城；核心质量与延迟可测 |
| P1 城市与动画 | 公开居民与事件 fixture、同步基础 | 地图、寻路、镜头、动画、点击卡片 | 预制居民稳定活动；事件可消费 |
| P2 手机与生成 | 日语手机完整流程、授权、问卷、队列与恢复 | 真实生成模块、预览素材与质量回退 | 手机独立完成预览及确认入城 |
| P3 AI 与互动 | 日语文本服务、安全过滤、用量与预算 | 人格行为、社交调度、气泡与卡片 | 两角色完成安全日语对话且动画不阻塞 |
| P4 展场验收 | 并发、权限、费用、删除及网络故障测试 | 目标设备性能、视觉质量、离线和长时间测试 | 双方验收清单完成，失败项有处理结论 |

### 成本与资源

A 统计每位访客的外观抽取、图像增强、文本请求、失败重试、Cloud Run、Firestore、Cloud Storage 和网络费用，另统计每小时城市对话成本。按 100、500、1000 位参与者与实际活动时长做情景估算。单张图片输出示例不能作为完整项目报价；模型、平台、区域及价格须在立项时重新核对。

展示设备建议为 11–13 英寸、较强 WebGL 性能的平板，原计划建议 8GB RAM 或以上；最终以实际设备测试为准。现场准备稳定供电、支架、防休眠设置、网络和备用联网；全身照可由工作人员协助、支架自拍或相册上传。

### 主要协作风险

B 同时承担角色生产和城市画面，可能成为瓶颈。P0 应量化模板覆盖率和人工修正时间，优先缩减个性化种类；A 在接口稳定后承担素材上传、自动校验基础设施和运营工具，避免重复修改 B 的视觉模块。

## 9 验收交付与完成标准

| 验收项目 | 通过条件与证据 | 负责人 |
| --- | --- | --- |

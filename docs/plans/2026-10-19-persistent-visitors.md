# 访客持久化与权限实施计划

Owner：A / Main。用户在下一步建议后明确回复 do it，授权本轮实施。基于 f7b527e，分支 codex/persistent-visitors。

## 范围与设计

沿用现有插画、日语参加/分项确认/撤回 UI 和公开 DTO。新增默认关闭的访客 API，使用服务器产生的 256-bit 匿名设备会话；HttpOnly/SameSite cookie 保存凭证，Firestore 只存 SHA-256。会话不代表核实真人身份，不替代照片或真实个人资料的授权。

Firestore STANDARD / Native，项目既有 (default) 东京实例；本轮只对 demo-ai-city 本地 emulator 写入，真实项目只读查询版别。所有客户端规则维持 deny-all，服务器通过应用层所有权/角色和未来 runtime IAM 控制。没有内存 fallback。新增云端开关、明确 project/namespace 与 HTTPS origin；发布需具体成品后的独立权限/部署确认。

会话、任务、同意及公开字段分开保存，事务保证并发确认幂等、删除后不复活和当前任务唯一。私有输入不进公开快照。重建 Node 服务后恢复访客会话、任务、公开住民及 stream。设备管理登录与配对仍沿用现有短期会话，重启后重新登录/配对；不会把其内存状态冒充持久化完成。

安全审查后补充：新访客只能凭管理员发出的 3 分钟一次性邀请入场，最多 10 个有效邀请和 200 个会话；任意猜测的 cookie/邀请码先经独立稳定 HMAC 验证，无效者不读数据库。有效凭证每进程每分钟最多 60 次请求。邀请兑换不作无凭证重放：如 Set-Cookie 响应丢失，管理员重发新邀请。新会话先持有 3 分钟 pending lease，首次有效本人读取/操作确认后变成原始创建时间起 24 小时会话；不延长到期时间。未确认 lease 到期即无权限，后续合法管理/清理事务释放位置。过期数据采用访问时清理，未配置后台 TTL，因此不能承诺到期立即物理删除。

云端还必须显式开启 mock 设备管理 API、稳定管理 key、独立访客 HMAC key、明确 namespace 和 HTTPS origin。启动配置错误失败关闭，禁止临时 key 或降级到内存。正式公网的入口限流、预算及新数据库 IAM 属部署前独立操作。

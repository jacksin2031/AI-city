# 正式展示体验实施计划

**目标：** 让参与者在明确同意后使用照片生成角色、回答问卷、在城市展示并参与受控 AI 对话，同时将所有面向参与者和管理员的页面按真实状态交付。

**基础：** 复用现有 visitor、Spine 任务、城市播放器和对话服务。生产照片处理必须使用私有持久存储和独立 worker；本机文件系统与模拟器实现不能直接作为云端实现。

## 已确认的运营条件

- 沿用现有 Google Cloud 项目和角色制作工具；活动仅一天，用户决定暂不设置金额或每日角色数上限。记录用量、费用及调用结果，避免因重复投递或结果未知而重复调用。预算提醒不是强制断费机制。
- 用户确认展览期间本机保持开机并联网，作为角色生成工作机；云端不得保存或复制本机 Codex 登录凭据。
- 生成完成或取消后删除原照；失败照片最多保留 24 小时。工具创建的副本、运行中任务、失败重试和清理失败均须纳入删除策略；未确认删除时不得声称已删除。
- 页面和错误使用日语；未完成的功能不能标记为已上线。使用合成数据验证，不将 mock 测试当作真实模型或实体设备验收。

## 交付顺序与验收

1. **生产边界和契约。** 确认身份与本人会话、版本化的照片处理／外部模型／公开和对话同意，定义撤回、过期、失败、未知结果及恢复状态；更新严格契约、双方调用方和负向测试。原始问卷和照片不得进入公开数据或日志。
2. **私有存储与清理。** 增加受限云端对象存储和持久任务记录；实现完成、取消及 24 小时失败清理，覆盖工具副本、进程崩溃、删除失败和恢复。撤回优先阻止公开及素材访问，清理未完成时保持待处理。
3. **独立 worker 与用量监控。** 接入现有角色工具，记录不可变调用意图和用量；重复投递、租约失效和外部结果未知时不盲目重复付费。验证资源完整性、审核门槛及撤回与发布竞争，才允许发布。
4. **参与页面。** 合并照片、六题问卷、处理状态、预览、公开及撤回流程；明确说明服务提供者、用途、保存期、失败和公开范围。未启用的功能明确展示状态，不误称样本为生成结果。
5. **城市与对话。** 城市仅加载经过授权及完整性验证的角色；参与者对话须有独立授权，服务端仅使用允许的数据，并限制频率、内容和费用。测试取消授权、失败、不同意和素材加载失败。
6. **管理及展示页面。** 覆盖连接、状态、任务、用量、错误与恢复；验证手机及平板的权限和同步，保持日语文案。
7. **发布验收。** 运行 `pnpm check`、规则和浏览器回归；在隔离环境验证全流程及删除，再使用明确授权的照片和受控模型调用验收；检查真实设备、不同网络、恢复和长时间表现。先零流量部署验证，再依据实际结果切换。

## 尚待确定

- 云端照片、工具工作目录和素材的实际隔离／清理机制；现有工具按摘要保存副本，不能只删除入口照片。
- Cloud Storage 新桶默认软删除保留 7 天；2026-11-05 的只读检查显示现有 `ai-city-511822-private` 桶也是 7 天，不能满足已确认的删除期限。如使用该服务存照片，必须在接收任何照片前为专用桶确认软删除关闭、版本控制及保留策略不会留存副本，并验证实际删除；不得修改其他已有桶。参见 https://docs.cloud.google.com/storage/docs/soft-delete 。
- 生产素材及 Spine Runtime 的适用授权、照片处理对外说明与目标展示设备；这些条件须有实际证据，不能从示例素材推定。

## 本机清理进度

- 发布事务写入持久的照片待清理标记；独立本机 worker 删除入口照片，失败时重试，且清理故障不删除已经发布的角色素材。
- 若工具工作目录仍存在，不能仅凭发布成功证明子进程已经退出；保留目录和待清理状态。当前尚无可验证的工具进程树退出证明，因此这不是完整照片清除，也未满足正式版保存期限。
- 现有真实角色工具依赖本机 Codex 登录和内置生图。它不是可直接以现有 Cloud Run 身份运行的云端服务；不得把个人登录凭据复制到镜像或当作已经完成的生产接入。
- 新增只读桶策略检查 `pnpm exec tsx apps/web/scripts/verify-photo-bucket.ts BUCKET`，校验区域、公开访问防护、统一桶权限、版本、保留与软删除。它尚未接入任何云端照片上传路径；通过检查不等于 IAM、历史对象、策略传播或实际删除已验证。
- 本机轮询器可回收写入后、任务登记前进程中断而遗留的照片：24 小时后对无任务记录的文件先原子保留清理标记，再删除；同一事务边界阻止迟到任务建立。删除失败可重试，已有任务的照片不会按孤儿文件删除。该机制依赖文件时间和持续运行的本机轮询，不能保证关机或故障时严格在 24 小时内完成，也没有实现云端回收。
- 已添加未启用的 Cloud Storage 照片适配器：安全桶策略检查、只创建新对象、限制读取大小、按 generation 读／删、删除后检查当前对象与桶策略。内部编排先预留再上传，按返回的 generation 回读并核对摘要后排队。仅以替身存储和 Firestore 模拟器测试；尚未连接 ADC、网页、worker 或真实桶。上传结果未知、上传中途退出及策略并发变化仍须由恢复与回收机制处理，不得启用云端接收。
- 新增内部云照片预留与事务状态：上传前记录绑定本人会话的处理、外部上传和自动公开同意及照片摘要；取消未开始的上传会封存任务 ID，取消已开始的上传保持 `CLEANUP_PENDING`；服务端独立核对摘要和 generation 后才可事务排队，旧本机 worker 不认领云照片任务。接口尚未对浏览器开放，上传编排、超时未知结果、取消后回收和清理器均未实现；完成与取消竞争时，如完成先提交，调用方仍须对已排队任务执行撤回，不能将普通取消失败视为撤回成功。

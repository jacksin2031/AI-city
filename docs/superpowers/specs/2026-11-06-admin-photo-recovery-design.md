# 管理端「照片生成」监控与紧急修复 设计

状态：待用户审阅（尚未实现） 日期：2026-11-06 Owner：Shared

## 1. 为什么做

展出现场，照片生成角色出问题时，管理者目前**什么都看不到、什么都做不了**：

- 想知道「哪里出错了」：Worker 是否还在运行、谁的任务卡在哪个状态、卡了多久，都没有任何地方可看。
- 想「修好」：任务失败只会对参加者显示「请找工作人员」，管理者没有任何可按的处理；已生成的角色如果头发、手、脚位置歪了，也无法调整。

目标是让管理者（以及现场工作人员，他们同样是管理员）在手机上，紧急时能**看见问题、换掉坏角色、微调歪掉的部位**。

## 2. 目标 / 非目标 / 反目标

目标

1. 管理页一眼看出照片 Worker 是否在线，以及排队、处理中的人数。
2. 列出每位照片参加者的任务状态和卡住的时间，异常状态排在最前面。
3. 角色没做出来时：取消、让 Worker 重做（花钱，需二次确认）、改成 6 个官方预设角色之一并立刻出现在地图上。
4. 角色已生成但头发、手、脚位置歪时：在手机上调整位置和大小，即时预览，可保存、可还原。
5. 每次修复留下记录。

非目标

- 不用 AI 重画单个部位（位置歪，而不是图画坏，是用户确认的主要问题）。
- 不做角色权限分级：所有管理员权限相同，沿用现有登入方式。
- 不改参加者的公开范围或同意记录。
- 对话 Worker 不纳入状态显示（默认关闭）。

反目标（即使技术上做成也算失败）

- 管理者或工作人员能看到参加者**原始照片**。
- 不经确认就触发会花钱的外部模型调用。
- 调整或换角色后，公开出去的内容比参加者当初同意的更多。
- 原始已验证的角色文件被改动（它们带哈希校验，必须保持不可变）。

## 3. 现状（已读代码确认的事实）

- 管理页 `apps/web/app/admin/` 只有：展示操作（模式、动画、休止）、连接平板、邀请参加者、见本角色增减、累计人数、「公开中的住民」清单（搜索、删除）。没有任何任务视图。
- 照片任务状态共 8 种（`packages/contracts/src/spine.ts`）：`QUEUED` `RUNNING` `PREPARED` `UNKNOWN` `REQUIRES_REVIEW` `FAILED` `PUBLISHED` `WITHDRAWN`。目前只有参加者本人的手机看得到。
- 任务记录存在参加者存储的 `jobs/spine-<task>`（`apps/web/lib/spine/jobs.ts`，带严格的状态不变量：非撤回状态必须有照片哈希和同意，`PUBLISHED` 必须有 bundle）；名册在 `meta/state.spineResidents`。
- Worker 在本机运行（`scripts/cloud-spine-worker.ts`，每轮调用 `pollCloudSpineTasks`），通过 Firestore 拉取任务。**没有心跳**：它停了，云端没有任何异常。
- 管理 API 是 `apps/web/lib/link/http.ts`：以 `ai-city-link` Cookie 的管理员令牌授权，路径有 `admin`、`control`、`preset`、`remove` 等。管理服务（`DeviceLinkService`）目前只通过 `participation` 读取公开快照，不接触 Spine 任务。
- 已发布角色是一组不可变文件（骨架、图集、图片、朝向策略、构建清单），平板用 `sha256` 校验后才使用（`packages/city/src/spine-bundle.ts`）。朝向策略已经有「按方向调整」的机制（`spine-orientation.ts`），可作为调整层的参照。
- 已有「不用 AI、约 0.03 秒产生」的标准手臂做法（实施前需确认能否套用到腿、手）。

## 4. 设计

### 4.1 Worker 心跳

- Worker 每约 30 秒写入一条心跳：时间、正在处理的任务数、排队数、当前动作（闲置／处理第 N 位）。
- 管理页读取它：最近 2 分钟内有心跳为绿色，否则红色并显示最后心跳时间。
- 心跳只含数字和时间，不含任何参加者资料。
- 阈值（2 分钟）、间隔（30 秒）是**我的默认值**，实现时做成可配置。

### 4.2 管理端任务清单

- 管理页新增「照片生成」区块（手机优先，日语）：顶部为 Worker 状态条，下面每位参加者一列：生成后角色的缩图、状态标签、停留时间。
- `FAILED` `UNKNOWN` `REQUIRES_REVIEW` 标红置顶；长时间停在 `RUNNING` 也要醒目（阈值默认 15 分钟，我的默认值，典型一人约 7 分钟）。
- 只显示：任务编号的短码、状态、时间、生成后的角色缩图。**不显示昵称以外的个人信息，不显示照片。**

### 4.3 角色没做出来时的处理

对 `FAILED` `UNKNOWN` `REQUIRES_REVIEW`（以及长时间 `RUNNING`）的任务，点开后可选：

1. **取消任务**：把任务结束，并走既有的撤回与照片清理流程。
2. **让 Worker 重做**：把任务放回队列。**会再次调用外部模型、花钱，必须二次确认**，并受现有的实机调用预算（`live-budget`）约束。
   - 重做依赖原始照片仍在私有存储中。照片已被清理（例如任务早已完成）时重做不可用，界面要明确说明原因，而不是让按钮失败。
   - 现有任务状态机不一定允许 `FAILED` / `UNKNOWN` 回到 `QUEUED`，实现者需要在 `lifecycle` 中新增受控的转换，并保持 `jobs.ts` 的不变量。
3. **改成预设角色**：从 6 个官方预设角色选一个，立刻以该参加者的身份出现在地图上；原任务按「取消」处理（含照片清理）。

「改成预设角色」的实现必须守住任务记录的状态不变量（`PUBLISHED` 要求有 bundle），推荐做法：在名册里为这位参加者新增一种「预设角色」条目，复用不用照片流程已有的 `sample-<id>-v1` 头像版本，而不是伪造 bundle。具体数据形状由实现者设计，但不得放宽 `jobs.ts` 的校验。

### 4.4 位置调整（头发、手、脚）

- 只调整已生成并已发布角色的**位置和大小**：头发、左右手、左右脚，各自有上下、左右、缩放。
- **不改动原始文件**：另存一份「调整值」（每个部位的位移和缩放，带范围上限），绑定到该角色的 bundle 版本。平板绘制时在既有朝向策略之后套用调整值。
- 手机上显示该角色预览，拖动滑杆即时看到效果，可「保存」或「还原」；还原即删除调整值。
- 调整值有硬性范围（例如位移不超过角色高度的一定比例、缩放在 0.5–1.5 倍），防止拖到离谱位置。具体数字由实现者在查看真实角色后定。
- 调整值如何送到平板：随公开快照中该角色的头像信息一并下发（需扩展快照的可选字段，同时更新 contracts、fixtures 和测试）。

### 4.5 修复记录

- 每次取消、重做、改预设、保存或还原调整，写一条记录：时间、动作、任务短码。
- 因为所有管理员权限相同，**不记录是谁按的**（我的决定）。
- 管理页可看最近的记录。

### 4.6 不变的边界

- 修复动作只在已有的参加者同意范围内进行；换成预设角色不会多公开任何东西，参加者昵称沿用其公开项勾选结果。
- 所有面向管理员的文案是日语；项目文档为简体中文。
- 默认开发是离线 mock：mock 模式下任务清单和修复区块要能显示为空或示例，不得假装连上了真实 Worker。

## 5. 约束

- 不提交或打印凭证、照片、真实用户数据。
- 凡会调用付费模型的动作需明确确认；不得因为存在云端配置就假定可以调用。
- 管理 API 沿用现有管理员令牌与速率限制；新路由要有输入校验和针对错误边界、权限的测试（`AGENTS.md`）。
- 手机优先，触控目标不小于现有管理页的按钮尺寸。
- 修改共享 schema 前检查双方调用方，更新 fixtures 和测试。

## 6. 留给实现者决定

- 心跳与调整值在存储中的具体路径和文档形状。
- 标准骨架里头发、手、脚对应的骨骼／槽位名称（本设计未读取真实 bundle；需要先检查 Spine 工具生成的骨架）。
- 改成预设角色时名册条目的具体形状和过期规则（需与参加者 session 24 小时有效期一致）。
- 调整值的范围数字，以及是否也套用到「手腿标准款」一键替换（需先验证可行）。
- 管理 API 如何取得参加者存储中的任务（管理服务目前只依赖 `participation`，需要决定新增的依赖注入方式，并保证 mock 模式仍可运行）。
- Worker 写心跳需要的 Firestore 写权限：现有本机 Worker 使用开发者自己的 ADC，实现时确认不需要扩大任何 IAM。
- 管理页是否做成独立路由还是放在现有页面的新区块。

## 7. 我的决定（请审阅）

1. 工作人员看不到原始照片，只看生成后的角色缩图。
2. 修复记录不记录个人身份，只记时间、动作、任务短码。
3. Worker 状态只显示照片 Worker，不含对话 Worker。
4. 心跳间隔 30 秒、离线判定 2 分钟、`RUNNING` 异常阈值 15 分钟。
5. 位置调整用「叠加调整值」，不重新打包角色。
6. 「改成预设角色」放进名册新条目，不伪造 bundle。

## 8. 验证思路

- 单元：心跳在线／离线判定；调整值范围校验与还原；状态不变量在「取消」「重做」「改预设」后仍成立；管理路由的认证、输入校验和错误边界。
- 隐私：任务清单与管理 API 的返回里不出现照片或其存储路径（专门的测试）。
- 成本：「重做」未经确认时不调用模型；超出预算被拒绝。
- 浏览器：手机尺寸下 Worker 状态、任务清单、预览与滑杆；平板上调整值生效、还原后恢复。
- 实机：在真实平板上确认调整后的角色位置，不能以 mock 测试代替。

# Spine 角色生产流程整合设计

## 目标与现状

参与者提交照片并明确授权后，系统自动制作角色，在满足发布条件时自动加入城市；处理中、失败、取消和撤回均有清楚状态。当前 AI City 的参与、发布和城市人物仍以 mock 为主，城市 renderer 使用示范插画；Spine Skin Tool 是独立的本机 Python 工具，输出 Spine Runtime JSON、atlas、PNG 和方向守卫，并非现有 AvatarManifest 接受的图片集。现有发布同意在生成后取得，不能直接用于授权照片上传或自动发布。

## 路径与取舍

1. **推荐：受控独立 worker + 共享契约。** AI City 负责会话、照片同意、私有存储、任务和发布；worker 复用现有工具的 pipeline，城市只读取公开运行素材。职责分明，可保留恢复、限额和撤回边界，但需要建设真实后端和运行环境。
2. 将工具直接嵌入 Next.js 请求进程。上线简单，但长时间生图、进程重启、私有照片、锁定 Python/Node 版本和多实例恢复难以保证，不采用。
3. 预生成并人工导入运行包。实现较简单，但不能完成参与者提交后的自动生产，不符合目标。

## 目标流程

1. 参与端展示日语说明，区分照片处理、外部模型上传及角色自动公开范围，记录与本人会话绑定的版本化同意；不同意则不上传或制作。
2. 服务端验证会话及图片类型、大小和解码限制，去除不需要的元数据，写入私有存储；创建持久任务并绑定照片、同意记录及角色 ID。前端不直接调用模型或持有服务凭证。
3. 持久队列由隔离 worker 领取，worker 使用受控接口导入照片并调用现有 `pipeline_service`，保留工具的预算、幂等、租约、恢复和未知结果语义。外部调用可能已发生而结果未知时停止并收取，不盲目重发。
4. 仅已验证完整性、授权有效且符合工具现有审核及发布条件的运行包可进入公开素材区。审核未通过、未知、参考素材不可用或授权撤回时保持未发布，提供日语状态；不得将技术组装成功或模型辅助结果伪称人工或生产批准。
5. 发布前在服务端再次验证会话、同意、撤回及候选版本，原子地提交公开角色与事件；重复执行不得创建重复人物。用户要求全自动发布，不增加人为确认步骤；若工具既有发布门槛需要人工证据，停在待审核并如实报告，不伪造通过。
6. 城市使用已验证的公开 Spine 资源，按方向、动作和方向守卫播放；加载失败时明确显示占位状态，不能把示范头像冒充真实结果。撤回立即停止公开显示，处理正在执行的任务和私有／公开素材清除；失败可恢复并留可审计状态。

## 边界和设计约束

- 修改共享契约前检查 A/B 调用方：为 Spine Runtime 包定义版本、受限资源引用、完整性、动画及方向守卫，不使旧图片 manifest 失效；更新 fixtures、版本说明和负向测试。
- 照片、设计和任务详情只能由授权服务及 worker 访问，公开数据不包含原照、密钥、模型上下文或完整问卷。拒绝路径穿越、任意 URL 和未经校验的包；资源撤回与缓存策略须可验证。
- 默认不开启真实上传、真实模型、云资源或公众访问。实现可在本地以合成图片、替身 worker 和隔离存储验证；真实运行须单独配置、本人授权及合规素材。不能根据工具历史验收推定素材再分发许可或任意照片质量。
- 继续使用工具已有生成、审核、装配和状态机，不另造模型调用层；尊重工具锁定依赖和 loopback 服务边界。生产 worker 的运行方式、持久存储、恢复与隔离需要实测，不将本地 mock 称为生产能力。
- 每阶段给出清晰可恢复的状态；授权撤回与完成回调竞争时不得重新发布。模型超时、队列重复、服务重启及未知结果均须覆盖。

## 验收与实施顺序

1. 首先确定版本化接口及授权／状态语义，包含旧客户端兼容、拒绝非法资源和不同意时无上传的测试。
2. 实现合成素材的完整本地链路：提交、私有存储、假 worker、持久状态、批准候选、自动发布、城市播放、撤回及失败恢复；浏览器验证日语状态与控制台。
3. 接入真实独立 worker 和受控存储适配器；验证重启、重复执行、并发撤回、超时未知和资源完整性。真实模型调用默认关闭。
4. 经明确授权和许可检查后，才以真实照片、参考素材和目标设备做端到端验收；记录实际费用／调用及未验证项。目标设备性能、视觉品质和长期可靠性不能由合成测试替代。

## 尚需决定的运营条件

真实部署位置、照片保存期限、服务提供者和对外展示的授权文案应在启用真实服务前确定；目前仓库没有可直接证明的生产授权存储及可公开再分发的参考素材。自动发布不能越过当前工具的审核／生产批准要求，除非另行修改并验证适用的发布政策。
